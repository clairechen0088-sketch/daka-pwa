# 每日结算一致性修复

`Engine.settle()` 在一个 Dexie 读写事务内执行重复检查、任务生成、积分发放、连续打卡里程碑、保护卡、每日汇总、任务锁定、连续状态和孩子余额同步。

事务覆盖 `dailyTasks`、`dailySummaries`、`pointRecords`、`streak`、`streakAwardRecords`、`protectionCardRecords`、`child`，以及任务生成和规则读取所需的 `taskTemplates`、`rulesConfig`。数据库异常直接向调用方抛出，整个事务回滚。事务完成后才向页面返回成功。

事务回调必须声明为 `async`，让仓库自带的 Dexie 4.0.11 正确跟踪原生 async/await 的事务上下文。事务内只等待数据库操作和本地计算，不添加网络或计时器等待。

## 重复结算与旧版部分结果

- 同一数据库上同时点击或从多个页面发起结算时，IndexedDB 将重叠的读写事务串行执行。后续请求在事务内看到已存在的汇总后停止，不再发分。
- 汇总、已结算任务或任务的积分流水引用仍作为防重依据。
- 若当日没有汇总但已有 `taskEarn`、`basicStudyBonus`、`streakBonus`、里程碑记录或关联里程碑的保护卡奖励，停止结算并提示核对历史，避免旧版残留造成重复发放。
- 不根据猜测删除、补发或覆盖旧记录。这些旧版异常记录需要结合历史流水核对后单独处理。此补丁并不意味着已有用户实际发生过重复计分。
- 同日兑换、退款、手动积分或其他孩子的记录不会阻止结算。
- 仅发保护卡的里程碑不再错误关联上一条任务积分流水。

家长页面增加执行中保护，结算完成前不重复提交或切换结算日期；失败后恢复按钮。如果数据库已提交但页面刷新失败，明确提示结算已完成，避免将显示错误误报为结算失败。

## 验证

使用 Node.js 22 或更高版本：

```sh
npm ci
npm test
npm run check-pwa
```

真实浏览器验证（首次运行先安装 Chromium）：

```sh
npx playwright install chromium
npm run test:browser
```

受限运行环境可通过 `DAKA_CHROMIUM_PATH` 指向已安装的 Chromium 可执行文件。

自动化测试加载实际 `src/db.js`、`src/engine.js`、`src/rules.js` 与仓库自带的 Dexie，通过 `fake-indexeddb` 为每个测试建立独立数据库，不访问用户浏览器的 IndexedDB。

覆盖正常计分、熏听封顶、基础完成奖励、七日里程碑积分和保护卡、重复调用、五个并发调用、独立数据库连接、七处真实写入后的故障、数据库写入拒绝、首次任务生成/连续状态创建回滚、异常后的正常重试、旧版残留拒绝、零积分结算，以及与奖励兑换并发和退款的兼容性。回滚测试逐表对比结算前后快照，并验证重试后的流水、汇总、任务、里程碑、保护卡和积分余额。

另有 6 项 Chromium 原生 IndexedDB 验证：两个标签页并发结算、晚期写入失败与重试、家长页面重复提交及日期锁定、页面失败恢复按钮、提交后显示错误提示，以及 PWA 断网重载/结算/再次重载后历史保留。浏览器测试使用全新的隔离配置，不打开用户已有浏览器数据。CI 在 PR 和修复分支中运行上述检查。

## 数据与离线兼容

不修改数据库名、版本、schema、初始化或备份导入逻辑，不调用数据库清空、删除或历史重算。`fake-indexeddb` 和 Playwright 仅为开发测试依赖，浏览器继续使用已有的本地 Dexie，结算没有新增网络依赖。Service Worker 的缓存与离线策略保持原有实现，部署工作流仍负责更新缓存版本。
